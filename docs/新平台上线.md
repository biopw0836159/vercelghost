# 新平台上线要做什么

**结论：通常什么都不用做。** 平台清单是动态的 —— 后台一发出资料，新平台就会自动
出现在勾选清单里，也会自动被 `ALL` 查询涵盖。不需要改代码、不需要重新部署、
不需要通知任何人。

唯一「建议顺手做、但不做也不会漏资料」的一件事，见下面第 2 节。

---

## 1. 自动生效的部分

平台清单的唯一来源是 [`lib/platforms.ts`](../lib/platforms.ts)，它做两件事：

- `getPlatformList()` — 取当期实际有资料的平台，给 `/api/platforms` 产生勾选清单
- `resolvePlatforms()` — 把使用者填的 `ALL` 展开成实际清单（C 引擎与新进会员
  这两支后端不吃 `ALL`，直接传会回 0 笔）

两者都从**彩票（lottery-stats）+ 外接（external-game-stats）取联集**。
取联集是因为新平台上线初期常常只有一边有流水（例如先开外接、彩票还没开），
只看彩票会让整个平台在清单里看不到。

清单只快取 **3 分钟**，所以后台发出资料后最多 3 分钟就会出现。

> 这个 TTL 是刻意压短的，不跟着「历史日期已定型」给 30 分钟。
> 2026-08-15 实测踩过：后端某次回应少了 LS（连打三次都是 18 个，只有那次 17 个），
> 被快取半小时，期间查询就静默少算一整个平台。结构性资料错一次的代价太大，
> 宁可多打几次后端让异常自愈。

## 2. 建议顺手做：加进系统分组对照表

[`app/api/platforms/route.ts`](../app/api/platforms/route.ts) 有一张 `SERIES` 对照表，
决定平台在画面上归到 DY / KR / LJ 哪一堆。

**没加也不会漏资料** —— 不在表里的平台一律归到「其他」照样列出、照样查得到，
只是分组不好看。有空时补一行即可：

```ts
DS: 'KR',   // 鼎上，威廉市场，2026-08 上线
```

注记市场（阿森／威廉／事务）纯粹是给人看的，程式不使用。

## 3. 上线首日可能看到的正常现象

| 现象 | 原因 |
|---|---|
| 平台按钮标着 `·外` 或 `·彩` | 目前只有单边有流水。切到另一边查到 0 笔是正常的，不是故障 |
| 平台还没出现 | 后台该日还没发出任何资料。等资料出来，最多 3 分钟后自动出现 |
| 平台归在「其他」系列 | `SERIES` 对照表还没加，见第 2 节。不影响查询结果 |
